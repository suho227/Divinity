- Configuration: Server-side with getRequestConfig

4. Key Configurations & Implementation Details
================================================================================

[Routing & Internationalization]
- Next.js middleware (`src/middleware.ts`) handles locale prefix routing
- Route pattern: `/` or `/(ko|ja|en|zh)/:path*`
- Default locale fallback: 'ko' (Korean)
- Locale detection: Request-based with fallback to default
- All routes are wrapped in [locale] parameter for multi-language support

[Sanity CMS Integration]
- Project ID: o656ekmv
- Organization ID: oWQyIjvX6
- Dataset: production
- Studio URL: http://localhost:3000/studio (when dev server running)
- Plugins: structureTool (replaces older deskTool)
- Features:
  * Rich text editing with PortableText
  * Image optimization
  * Real-time content editing
  * Schema-driven content validation

[TypeScript Configuration]
- Target: ES2017
- Strict mode: Enabled
- Module resolution: bundler
- Path alias: @ → ./src/
- JSX: react-jsx (React 19 compatible)
- Incremental compilation: Enabled

[ESLint & Code Quality]
- Config Format: Flat config (eslint.config.mjs)
- Base configs: Next.js core-web-vitals + TypeScript
- Includes: Core Web Vitals linting, TypeScript linting
- Ignored paths: .next, out, build, next-env.d.ts

[Tailwind CSS]
- Version: 4.x (PostCSS-based)
- Plugins:
  * @tailwindcss/postcss (4.1.18)
  * @tailwindcss/typography (0.5.19) - for rich text content
- Processing: Via postcss.config.mjs with autoprefixer
- Global directives: In src/app/globals.css

[Supabase Setup]
- Authentication: Session-based (cookies)
- SSR support: @supabase/ssr for server-side rendering
- Database: PostgreSQL (via Supabase managed DB)
- Auth flow: Cookie-based authentication with middleware
- Server client: src/utils/supabase/server.ts

8. Development Workflow
================================================================================

[Getting Started]
1. Clone repository
2. Install dependencies: npm install
3. Set up .env.local from .env.local.example template
4. Run dev server: npm run dev
5. Open http://localhost:3000 in browser
6. Sanity Studio accessible at http://localhost:3000/studio

[Working with Content]
- Edit dynamic content (notices, about info) in Sanity Studio
- Changes reflect immediately via live content queries
- Uses GROQ queries for flexible data fetching

[Adding New Pages]
- Create file under src/app/[locale]/{feature}/page.tsx
- All routes automatically localized via [locale] parameter
- Add translations to messages/*.json files

[Working with Multilingual Content]
- Use next-intl hooks: useTranslations(), useLocale()
- Message keys centralized in /messages/*.json
- Locale prefix handled automatically by middleware & router

9. Technology Rationale
================================================================================

[Next.js 16]
- App Router for modern, file-based routing
- Server Components for optimal performance
- Built-in Image optimization
- Automatic static optimization

[Sanity.io]
- Headless CMS allows flexible content architecture
- Real-time collaborative editing for admin team
- GROQ query language for precise content fetching
- Fully customizable schema and validation

[next-intl]
- Seamless integration with Next.js App Router
- Server-side i18n without client-side weight
- Type-safe translations
- Route-based locale detection

[Supabase]
- Open-source PostgreSQL database platform
- Built-in authentication with multiple providers
- Real-time subscriptions for live data
- Row-level security for data protection

[Tailwind CSS v4]
- CSS-first configuration (no JavaScript config needed)
- Better performance and smaller bundle size
- Built-in responsive design utilities
- Plugins for extended functionality

13. Common Tasks & Quick Reference
================================================================================

[Add New Language]
1. Create messages/{locale}.json with translations
2. Update i18n.ts to include new locale in array
3. Add to URL routing pattern in middleware.ts
4. Test at /{locale}/

[Query Sanity Content]
- Use GROQ query language
- Example: *[_type == "notice"] | order(_createdAt desc)
- Test queries in Sanity Vision (available in Studio)

[Debug Mode]
- npm run lint - Check for errors
- Check browser console for client-side errors
- Check terminal for server-side errors
- Sanity Studio: /studio/debug

[Production Checklist]
- Set all .env variables on deployment platform
- Run npm run build locally to verify build
- Test npm start locally
- Verify ESLint passes: npm run lint
- Check responsive design on multiple devices
- Test all locales
